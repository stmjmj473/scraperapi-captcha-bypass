## 验证码绕过到底怎么实现的

很多人搜"验证码绕过 API"其实想知道的第一个问题是：它真的能过 reCAPTCHA 和 Cloudflare 吗？

我的实测情况是这样的。ScraperAPI 在请求参数里加上 `render=true` 之后，它会在后端启动一个完整的无头浏览器实例来渲染页面。对于 Cloudflare 的 JS Challenge和 Turnstile，大部分情况下能直接拿到渲染后的 HTML，不需要你自己处理 cookie 或 challenge token。

但有个细节值得说。我抓一个用了 reCAPTCHA v3 的站点时，成功率大概在 85% 左右，不是 100%。失败的请求会返回验证码页面的 HTML 而不是目标内容。ScraperAPI 的处理逻辑是自动重试，但如果目标站的风控特别激进（比如绑定了行为分析），还是会有一定比例过不去。

说白了，它不是"破解验证码"，而是通过足够真实的浏览器指纹 + 住宅代理 IP 让目标站认为这是正常用户访问，从而不触发验证码，或者触发了低难度的挑战后自动完成。

## 和自建方案对比：什么时候该用、什么时候不该用

如果你自己维护过 Puppeteer + 代理池的方案，你会知道最烦的不是代码逻辑，而是代理 IP 的质量和更新频率。一个住宅代理池每月成本轻松上千美元，还要处理 IP 被封后的自动切换逻辑。

ScraperAPI 的价值就在这里：它把代理管理、浏览器指纹随机化、失败重试这些脏活全包了。你只需要发一个 HTTP GET 请求，传入目标 URL，剩下的它处理。

但如果你的场景是这样的，我建议别用它：

- 需要登录态保持（ScraperAPI 每次请求是独立 session，不支持跨请求保持 cookie）
- 需要执行复杂的页面交互（点击、滚动、填表），它只能拿到首次渲染的结果
- 日请求量超过千万级，这时候自建方案的单次成本会低很多

对于日请求量在几十万到几百万之间、主要做静态页面或简单动态页面抓取的场景，用 ScraperAPI 省下来的运维时间是值得那个月费的。

## 接入方式和代码示例

接入确实简单，这点没什么好吹的，因为本来就该这么简单。一个 API key 加到请求参数里就行：

```
GET http://api.scraperapi.com?api_key=你的KEY&url=目标网址&render=true
```

Python、Node.js、Go 都能直接用 HTTP 库调用，官方也有 SDK 但说实话直接发请求更灵活。我自己用 Python 的 requests 库加了个简单的重试装饰器，三行代码搞定。

顺带一提，它支持通过参数指定国家代码（`country_code=us`），这对抓取有地域限制内容的站点很有用。我抓日本站数据时切到 `country_code=jp`，成功率比不指定时高了大概 15 个百分点。

## 常见问题

不能。它对 Cloudflare JS Challenge、Turnstile、reCAPTCHA v2/v3 的处理能力比较强，但对于需要图片识别类验证码（比如滑块拼图、文字点选）的场景，成功率会明显下降。如果目标站用的是极验或者网易易盾这类国内验证码，建议先用免费额度测试再决定。

**render=true 和不开渲染有什么区别？**

不开渲染时，ScraperAPI 只是帮你换 IP 发请求，拿到的是服务器直接返回的 HTML。开了 render=true 后，它会用无头浏览器完整执行 JavaScript，等页面渲染完再把 DOM 返回给你。验证码绕过主要靠后者，但后者的响应时间会慢 3-8 秒，而且消耗的 API 额度是普通请求的 10 倍。
